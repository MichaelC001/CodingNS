# 手势与返回矩阵

这份文档只回答一件事：

- 新的左右侧页到底怎么开、怎么关、和返回键怎么配合

## 0. 返回到底怎么走

手机上的返回不看浏览历史，只看当前停在哪个页面。顺序固定为：

```text
会话消息页 → 会话列表 → 工作区首页 → 退出程序
```

触发方式：

| 平台 | 怎么触发 |
| --- | --- |
| Android | 系统返回键 |
| iOS | 从屏幕左边缘（24 像素以内）向右滑 |
| H5 移动端 | 不接管，保持浏览器自身行为 |

不管从哪个平台触发，都先看有没有弹层要关，再按上面的层级退页面。完整层级表见
`specs/spec009.1-移动端工作台导航与信息架构重构/docs/navigation-map.md` 第 5 节。

## 1. 对话页

| 场景 | 动作 | 结果 |
| --- | --- | --- |
| 对话主舞台 | 左滑 | 打开文件 / Git 左侧页 |
| 对话主舞台 | 系统返回 | 按第 0 节层级退页面 |
| 文件 / Git 左侧页 | 右滑 | 关闭侧页，回到对话主舞台 |
| 文件 / Git 左侧页 | 页面返回按钮 | 关闭侧页，回到对话主舞台 |
| 文件 / Git 左侧页 | 系统返回 | 先关闭侧页，不直接退路由 |

说明：

- 对话页的左侧页不抢系统边缘返回
- 文件和 Git 之间切换优先走页内标签，不走手势翻页

## 2. 助手页

| 场景 | 动作 | 结果 |
| --- | --- | --- |
| 助手主舞台 | 右滑 | 打开助手对话列表侧页 |
| 助手主舞台 | 左滑 | 打开当前助手右侧信息栏 |
| 助手对话列表侧页 | 左滑或关闭按钮 | 回到助手主舞台 |
| 助手右侧信息栏 | 右滑或关闭按钮 | 回到助手主舞台 |
| 任一助手侧页打开时 | 系统返回 | 先关闭当前侧页 |

说明：

- 助手页左右两边的职责必须固定，不能今天左边是列表，明天又改成信息
- 右侧信息栏内部标签切换不使用整页横滑，避免和开关侧页动作冲突

## 3. 终端页

终端页这次不重做手势模型，但要保证和新底部导航一致。

| 场景 | 动作 | 结果 |
| --- | --- | --- |
| 终端主舞台 | 现有左滑 / 抽屉入口 | 保持现有终端抽屉逻辑 |
| 终端列表抽屉打开时 | 系统返回 | 先关闭抽屉，不直接退页面 |
| 终端页 | 系统返回 | 按第 0 节层级退页面 |
| 终端页左边缘（28 像素内） | 右滑 | 打开终端列表抽屉；此时 iOS 返回手势让位，不触发 |

说明：

- 终端页左边缘已经有一套抽屉手势，同一个方向不能再塞一个返回动作
- 想返回上一层级时，避开这 28 像素，从稍微靠里的位置滑动

## 4. 弹层与返回

所有移动端弹层（sheet、侧页、抽屉、终端列表抽屉）打开时都会登记到同一个返回拦截栈，
返回键先关弹层，关完才轮到退页面。

| 场景 | 动作 | 结果 |
| --- | --- | --- |
| 任一弹层打开 | 系统返回 / 边缘滑动 | 关闭最上层弹层，地址不变 |
| 多个弹层同屏 | 系统返回 | 先关最后打开的那个 |
| 没有弹层打开 | 系统返回 | 按第 0 节层级退页面 |

## 5. 优先级规则

优先级从高到低：

1. 系统边缘返回
2. 当前已打开侧页 / 弹层的关闭
3. 页面内部明确横滑区域的开关动作
4. 普通内容区域的滚动

一句人话：
别抢系统返回，别让一个方向塞两套手势，别让用户滑一下就不知道自己去哪了。
