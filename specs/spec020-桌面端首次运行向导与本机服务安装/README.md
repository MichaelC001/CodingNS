# Spec 020：桌面端首次运行向导与本机服务安装

这个 Spec 解决一件事：用户下载安装桌面客户端之后，不再需要打开终端才能把服务跑起来。

当前桌面端只是个壳，本机没有服务时它既不报错也不引导，用户会看到一个连不上的登录页。用户唯一的选择是自己去命令行跑 `install.sh`，这对非技术用户基本走不通。

做法是给桌面端加一个首次运行向导：让用户选这台电脑是"只当客户端"还是"本机装服务"，客户端引导填地址并当场测通，服务端在界面里把服务装好、配好端口和开机自启。同时把"装服务"这件事抽成一份跨平台的 Node 脚本（`host-install.mjs`），桌面端和 `install.sh` 共用同一份逻辑，避免两套安装方式互相不认识。

顺带解决两个历史问题：Windows 上一直没有开机自启，以及自启依赖 pm2 这层多余的东西。

## 明确的边界

- 不把桌面客户端打包进 npm 包（已评估否决）。
- 不做"安装包内置 Node 和完整服务端"的一体化安装包，那会破坏现有签名流程、把安装包撑到 100MB 以上。
- 不改 Host 的业务逻辑、接口协议和数据库结构。

## 关键决策

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 安装逻辑写在哪 | 独立的零依赖 Node 脚本 | 桌面端和 `install.sh` 共用一份；Rust 写三平台分支成本太高 |
| 开机自启用什么 | 系统原生（LaunchAgent / systemd / 计划任务） | 少一层 pm2 依赖；Windows 侧正好补上现在的空缺 |
| 安装到哪 | 用户目录下的私有运行时 | 全程不需要管理员权限，不污染系统 |
| Node 从哪来 | 优先复用系统 Node，没有就下载私有 Node | 干净机器也能装通，同时不浪费已有环境 |
