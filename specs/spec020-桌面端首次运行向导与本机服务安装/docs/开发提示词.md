### 三、已经调研清楚的事实，不要重复调研

这些都是上一轮实际读代码确认过的，直接采信：

**前端怎么调 Rust 命令**
走 `apps/user-app/src/platform/platform-adapter.ts` 的 `invokeDesktopCommand`（第 239 行），它内部直接调 `window.__TAURI_INTERNALS__.invoke`，返回 `{ok: true, value}` 或 `{ok: false, errorCode, detail}`。
新增 Rust 命令只需要在 `apps/desktop/src-tauri/src/lib.rs` 的 `invoke_handler` 里注册，**不需要改 `desktop_bridge_plugin.rs`** —— 那个文件注入的 `window.CodingNSDesktop` 只给 iframe / 预览场景转发用。

**前端怎么收 Rust 事件**
已有先例：`apps/user-app/src/platform/platform-provider.tsx:160`，动态 `import("@tauri-apps/api/event")` 后调 `listen()`，组件卸载时 `unlisten()`。事件名常量和载荷类型放前端，写法参考 `apps/user-app/src/platform/desktop/window-events.ts`。`@tauri-apps/api` 已经在依赖里。

**配置读写在哪**
Rust 侧 `apps/desktop/src-tauri/src/config.rs`，配置文件名 `client-runtime-config.json`，存在 `app_config_dir` 下，补丁合并逻辑是 `if patch.x.is_some()` 的写法。
前端侧 `apps/user-app/src/config/client-config-service.ts`（读写）+ `client-config-store.ts`（订阅），类型在 `client-config-types.ts`。

**首屏为什么是白屏**
`apps/user-app/src/network/host-probe.ts:6-20` 探活失败不抛异常、只返回 `reachable: false`，导致 `LoginPage.tsx:305-326` 的 catch 分支永远不触发，所以页面上什么都不显示，只有点了登录才看到 `LoginPage.tsx:395` 的文案。默认地址硬编码在 `client-config-service.ts:117`（`http://127.0.0.1:3002`）。

**本机服务扫描**
前端 `apps/user-app/src/config/local-host-discovery-store.ts`，Rust 侧 `apps/desktop/src-tauri/src/host_discovery.rs`（用 `ps` / `powershell` 找 `codingns … start` 进程）。复用现有链路，不要新写扫描。

**中继连接怎么配**
`apps/user-app/src/config/relay-entry.ts` 的 `buildRelayEntryConfigPatch`，中继控制站固定在 `relay-control-site-config.ts`。路由入口是 `/connect/:tunnelDomain`。注意：仓库里**没有** `codingns connect` 这个 CLI 命令，用户说的"通过 connect 连接"指的就是中继。

**桌面端的能力边界**
没有 Node 运行时，没有 sidecar，没有 shell 权限（`Cargo.toml` 无 shell 插件，`capabilities/default.json` 只有 `core:default` 和窗口权限）。执行安装必须新增 Rust 命令，用 `std::process::Command`（`host_discovery.rs` 里已经在这么用）。
Rust 侧发事件用 `app.emit`（`lib.rs:983` 有现成写法）。

**仓库里没有 first-run / onboarding 机制**
`initialized` 都只是 store 加载完成的意思。`/bootstrap` 路由是建管理员账号的页面（`BootstrapPage.tsx`），不是安装引导。向导是从零加。

**install.sh 的现状**（2379 行）
- Windows 只认 `MINGW*|MSYS*|CYGWIN*`（401-410 行），**原生 cmd/PowerShell 跑不了**，桌面端不能假设用户有 Git-Bash
- **Windows 上完全没有开机自启**，`configure_startup` 只处理 macOS 的 LaunchAgent 和 Linux 的 systemd，Windows 落到 2217 行的 warning
- **没有静默模式**，所有交互从 `/dev/tty` 读，没有 tty 直接 die（333-345 行），只有 `CODINGNS_INSTALL_DRY_RUN`
- macOS 走 Homebrew 装系统级 Node，Linux 走 apt-get，Windows 用私有 npm prefix
- 用 pm2 托管服务

**Host 侧已有的安装相关实现**（可以参考，但向导场景用不上）
`apps/host/src/modules/client/service-update-task-service.ts`（任务式安装 + 进度查询）、`npm-global-package-service.ts`。它们跑在已经运行起来的 Host 里，而向导场景 Host 还不存在，所以不能直接复用。

**构建与签名顺序**
`scripts/build-desktop.sh`：`build_macos`(1058) → `release_macos`(1101) → `sign_macos_app`(1127) → `create_macos_release_dmg`(1130)。新增的 resources 是 `tauri build` 阶段写进 `.app` 的，早于签名，所以不影响签名和 notarization。
脚本会动态生成一份临时 tauri 配置（`prepare_desktop_tauri_build_config`，157 行），静态的 `tauri.conf.json` 改动照常生效。

**测试入口**
`pnpm test:related -- <变更文件>`、`pnpm --dir apps/user-app test ...`、`pnpm --dir apps/host test ...`。不要裸跑 `vitest` 或全量测试。

### 四、硬约束

1. **只改 `apps/user-app`**，不允许改已经下线的历史前端目录。
2. **界面文案必须走 i18n 字典**（`apps/user-app/src/i18n/zh-CN.ts` 和 `en-US.ts`），不允许硬编码显示文字。
3. **`host-install.mjs` 必须零外部依赖**，只能 import `node:` 内置模块。它要在 npm 包还没装好之前就能跑。
4. **安装全程不请求管理员权限**，不用 sudo，全部装在用户目录下。
5. **自启只写用户级**（LaunchAgent / systemd user / 用户计划任务），不写系统级目录。
6. **自启的"启用"动作必须在健康检查通过之后**，服务起不来时不能留下每次开机都失败的自启项。
7. 向导是整页流程；其中的浮层必须用 `DesktopModal`（移动端 `MobileSheet`），不允许手写弹层壳。
8. 不要编辑编译产物，不要把 js 文件加进 git。

### 五、已知的坑，优先验证

1. **Windows 计划任务的隐藏窗口**（最不确定的一处）。直接让计划任务跑 `node.exe` 会闪黑窗，方案里用 VBS 包装器隐藏启动。做任务 3.3 时**第一步就在真机上试这个**，不要等到最后。
2. **和旧 pm2 安装共存**。用户机器上可能已经有 `install.sh` 用 pm2 装的服务，检测逻辑必须覆盖 pm2 的 LaunchAgent 文件，否则会出现两个 Host 抢同一个端口。
3. **私有 Node 与系统 Node 并存**。走私有 npm prefix 后，用户在终端里敲 `codingns` 可能找不到，需要明确提示路径。
4. **国内网络下载 Node**。镜像回落必须真的可用，否则向导会卡在这一步。
