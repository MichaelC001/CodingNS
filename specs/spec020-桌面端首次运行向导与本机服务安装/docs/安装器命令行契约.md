# 安装器命令行契约（host-install.mjs）

这份文档说清 `packages/codingns/scripts/host-install.mjs` 怎么调、会输出什么、出错时怎么认。

桌面端向导（Rust 侧拉子进程）和 `install.sh` 都调它，两边看到的行为必须一致。改安装逻辑只改这一个文件。

## 这个脚本是什么

一份零依赖的 Node 脚本，只 import `node:` 内置模块。它要在 npm 包还没装好之前就能跑，所以不能引任何第三方包，也不能 import 仓库里的其他模块。

它负责：装服务包、写开机自启、启停服务、健康检查、写安装状态。

## 调用方式

```
node host-install.mjs <action> [options]
```

参数支持 `--key value`、`--key=value` 和开关式 `--flag` 三种写法。`--data-dir` 缺省是 `~/.codingns`。

## 动作

| 动作 | 参数 | 做什么 |
| --- | --- | --- |
| `check` | `--data-dir` | 读 `<数据目录>/runtime/install-state.json`，有就原样返回，没有返回 `null` |
| `status` | `--data-dir` | 返回安装与运行状态：`installed` / `running` / `pid` / `port` / `packageVersion` / `autostartEnabled` / `autostartKind` |
| `install` | `--port --data-dir --host --autostart --registry --package --version` | 完整安装：准备目录 → 装包 → 校验 → （可选）写自启 → 启动 → 健康检查 → （可选）启用自启 → 写状态 |
| `start` | `--data-dir` | 启动服务并等到可访问；已经配了自启就走自启机制拉起，否则直接后台拉起进程 |
| `stop` | `--data-dir` | 停服务：自启装的先停单元/任务，再按进程号兜底 SIGTERM，10 秒不退就 SIGKILL |
| `restart` | `--data-dir` | 先停再起 |
| `autostart` | `--enable` / `--prepare` / `--disable`，加 `--data-dir` | 写或移除开机自启；`--prepare` 只写文件不激活，`--enable` 写并激活 |
| `uninstall` | `--data-dir --purge` | 停服务 → 移除自启 → 删包；加 `--purge` 时连数据目录一起删 |

安装参数的默认值：

- 端口 `3002`
- 监听地址 `127.0.0.1`（要允许局域网访问就传 `--host 0.0.0.0`）
- 包名 `@jingyi0605/codingns`（`--package` 也可以给本地 tarball 路径）
- registry 默认 `https://registry.npmjs.org`，装失败会自动换 `https://registry.npmmirror.com` 重试一次

## 输出格式

stdout 每行一个 JSON 对象，也就是 `design.md` 里的 `HostInstallProgressEvent`：

```json
{"type":"step","stepId":"install-package","status":"running","label":"install-package","message":"安装服务包"}
{"type":"log","message":"用 https://registry.npmjs.org 安装失败，换镜像源再试一次。"}
{"type":"step","stepId":"install-package","status":"done","label":"install-package"}
{"type":"result","data":{"packageVersion":"2.1.0","port":3002}}
```

- `type` 取值：`step` / `log` / `download` / `result` / `error`
- `step` 行带 `stepId` 和 `status`（`running` / `done` / `failed` / `skipped`）
- 一次运行**最后一行**一定是 `result` 或 `error`
- 非 JSON 行不该出现；解析方遇到不认识的字段应当忽略

`install` 的步骤顺序（`stepId`）：

```
prepare-runtime → install-package → verify-package → configure-autostart?
→ start-service → health-check → activate-autostart? → write-state
```

带 `?` 的两步只在 `--autostart` 时出现。注意 **`activate-autostart` 排在 `health-check` 之后**：服务起不来时不会留下每次开机都失败的自启项。

## 退出码

| 码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1` | 一般失败（装包失败、健康检查超时、自启启用失败等） |
| `2` | 参数错误（动作不认识、端口非法、registry 非法） |
| `3` | 权限问题（正常情况下不会出现，安装全程都在用户目录里） |

## 错误码

出现 `{"type":"error"}` 时，`code` 字段是下面之一：

| 错误码 | 什么情况 |
| --- | --- |
| `UNKNOWN_ACTION` | 动作名不认识 |
| `INVALID_PORT` | 端口不是 1–65535 的整数 |
| `INVALID_REGISTRY` | registry 不是 http/https 地址 |
| `INVALID_AUTOSTART_OPTION` | `autostart` 没带 `--enable` / `--prepare` / `--disable` |
| `NPM_NOT_FOUND` | 找不到可用的 npm |
| `NPM_INSTALL_FAILED` | 官方源和镜像都装失败 |
| `PACKAGE_VERIFY_FAILED` | 装完了但版本不对或 CLI 入口不存在 |
| `AUTOSTART_FAILED` | 自启文件写好了但加载失败 |
| `HEALTH_CHECK_TIMEOUT` | 服务起来了但一直没响应 |
| `PERMISSION_DENIED` | 往目标目录写失败 |
| `PURGE_FAILED` | `--purge` 清理数据目录失败 |
| `INSTALLER_FAILED` | 其他未分类失败 |

`error` 行还带 `detail`（给排查用）和 `logPath`（本次运行的完整日志）。

## 日志

每次运行都会在 `<数据目录>/runtime/logs/<action>-<时间戳>.log` 留一份完整日志，包含每一步的命令和执行结果。排查安装问题时先看这里。

服务进程自己的 stdout / stderr 写在 `<数据目录>/runtime/logs/host-service.log`，和服务崩没崩、启动阶段报什么错直接相关。

## `codingns service`：给人用的快捷入口

上面这些动作平时不用手拼脚本路径，`codingns service` 就是它们的快捷方式：

```bash
codingns service status [--json]
codingns service logs [--tail 200] [--follow] [--kind service|install] [--path]
codingns service start | stop | restart
codingns service autostart --enable | --disable
codingns service install --port 3002 --data-dir ~/.codingns [--autostart]
codingns service uninstall [--purge]
codingns service check
```

约定：

- 除 `status`、`logs` 外，动作原样转发给安装器，**输出格式和退出码都不加工**，两边行为一致。
- `status` 默认输出给人看的摘要，`--json` 输出安装器原始结构。
- `status` 的展示层会认监督进程字段：如果状态里带了监督进程 pid，Host 没在跑时会显示“监督进程正在恢复”，而不是一句“未运行”。字段不存在时照常显示未运行。
- `logs` 默认看 `host-service.log`，`--kind install` 列安装日志，`--path` 只打印路径。

## 安装状态文件

`install` 成功后写 `<数据目录>/runtime/install-state.json`：

```json
{
  "schemaVersion": 1,
  "installedAt": "2026-09-16T02:00:00.000Z",
  "packageName": "@jingyi0605/codingns",
  "packageVersion": "2.1.0",
  "installPrefix": "/Users/you/.codingns/runtime/npm",
  "packageRoot": "/Users/you/.codingns/runtime/npm/lib/node_modules/@jingyi0605/codingns",
  "nodeBinary": "/usr/local/bin/node",
  "nodeSource": "system",
  "listenHost": "127.0.0.1",
  "port": 3002,
  "dataDir": "/Users/you/.codingns",
  "autostartEnabled": true,
  "autostartKind": "launchd",
  "autostartPath": "/Users/you/Library/LaunchAgents/com.codingns.host.plist"
}
```

`nodeSource` 是 `system`（用系统 Node）或 `private`（用桌面端下载的私有 Node）。

## 自启文件写在哪

| 平台 | 方式 | 路径 |
| --- | --- | --- |
| macOS | LaunchAgent | `~/Library/LaunchAgents/com.codingns.host.plist` |
| Linux | systemd user unit | `~/.config/systemd/user/codingns-host.service` |
| Windows | 登录计划任务 + VBS 包装 | 任务名 `CodingNS Host`，包装脚本在 `<数据目录>/runtime/autostart/codingns-host-launcher.vbs` |

Windows 用 VBS 包装是为了让计划任务以隐藏窗口方式启动，不闪黑窗；包装里用的是 `WScript.Shell.Run <命令>, 0, False`。

## 一个完整的例子

```
$ node host-install.mjs install --data-dir ~/.codingns --port 3002 \
    --host 127.0.0.1 --autostart
{"type":"step","stepId":"prepare-runtime","status":"running",...}
...
{"type":"result","data":{"packageVersion":"2.1.0","port":3002,"autostartEnabled":true,"autostartKind":"launchd",...}}

$ node host-install.mjs status --data-dir ~/.codingns
{"type":"result","data":{"installed":true,"running":true,"pid":12345,"port":3002,...}}
```
