# 导航与页面层级图

这份文档把移动端的页面层级钉死。

目的只有一个：

- 后面真正写 `router`、写移动端壳、拆 `WorkbenchLayout` 的时候，不再临时决定“这个入口到底该去哪”

## 1. 一级目的地

紧凑宽度下，一级目的地固定为 4 个：

1. `工作区`
2. `会话`
3. `工具`
4. `设置`

这 4 个入口不再随页面情绪乱变。

## 2. 页面层级

### 2.1 工作区流

```text
工作区
├── 工作区首页
│   ├── 导入工作区
│   ├── 克隆工作区
│   └── 进入工作区详情
└── 工作区详情
    ├── 会话概览
    ├── 文件入口
    ├── Git 入口
    ├── 终端入口
    ├── 进程入口
    └── 新建会话
```

规则：

- `工作区首页` 负责全局入口
- `工作区详情` 负责某个工作区内的上下文和二级切换

### 2.2 会话流

```text
会话
├── 会话索引页
│   ├── 最近会话
│   ├── 收藏会话
│   ├── 搜索入口
│   └── 进入会话详情
└── 会话详情页
    ├── 消息流
    ├── 输入区
    ├── 会话更多动作
    └── 工具入口
```

规则：

- `会话索引页` 负责找会话
- `会话详情页` 负责沉浸式对话
- 文件树、Git 面板、终端管理不再常驻在会话详情旁边

### 2.3 工具流

```text
工具
├── 工具首页
│   ├── 文件
│   ├── Git
│   ├── 终端
│   ├── 进程
│   └── 日志
├── 文件页
├── Git 页
├── 终端页
├── 进程页
└── 日志页
```

规则：

- `工具首页` 是辅助能力索引，不直接塞满复杂内容
- 进入重操作后升级为全屏子页

### 2.4 设置流

```text
设置
├── 设置首页
├── 连接与服务
├── 账号与安全
├── 外观与偏好
└── 关于与版本
```

## 3. 不同平台的导航承载

| 目标 | H5 移动端 | iOS | Android |
| --- | --- | --- | --- |
| 一级目的地 | 底部导航 | Tab Bar | Bottom Navigation |
| 列表到详情 | 页面 push / 路由切换 | Navigation Stack | Back Stack |
| 次操作 | sheet / 菜单 | sheet / action sheet / menu | bottom sheet / overflow menu |
| 重操作 | 全屏子页 | full-screen modal / push | fullscreen destination |

## 4. 路由意图建议

这里只定义意图，不强行限定最终实现语法。

建议至少有下面这些意图：

```text
/mobile/workspaces
/mobile/workspaces/:workspaceId
/mobile/sessions
/mobile/sessions/:sessionId
/mobile/tools
/mobile/tools/files
/mobile/tools/git
/mobile/tools/terminals
/mobile/tools/processes
/mobile/tools/logs
/mobile/settings
```

如果后续路由实现不是这个字符串，也至少要保留这套页面关系。

## 5. 返回规则

### 5.1 返回层级

手机上的返回不看浏览历史，只看当前停在哪个页面。顺序固定为：

```text
会话消息页 → 会话列表 → 工作区首页 → 退出程序
```

具体落到每个页面：

| 当前页面 | 返回后到哪 |
| --- | --- |
| 会话消息页 | 同一个工作区的会话列表 |
| 会话列表 | 工作区首页 `/workspaces` |
| 工作区首页 | 退出程序 |
| 对话消息页 | 对话列表 `/chats` |
| 对话列表 | 工作区首页 |
| 工具详情页（进程 / 文件 / Git） | 工具首页，和页面顶部返回按钮一致 |
| 其他一级页面（工作区详情、终端、插件、设置等） | 工作区首页 |

要点：

- 工作区首页是移动端的主页面，在这里再按一次返回才是退出程序
- 不存在“回到上一个访问过的页面”这种结果，用户从哪进来不影响返回去哪

### 5.2 弹层先关，再退页面

当前有弹层打开时，返回先关弹层：

1. 系统返回 / 边缘滑动
2. 已打开的弹层（sheet、侧页、抽屉、终端列表抽屉）
3. 按 5.1 退页面
4. 退出程序（只在工作区首页发生）

同屏有多个弹层时，谁最后打开谁先关。

### 5.3 各平台怎么触发返回

| 平台 | 触发方式 |
| --- | --- |
| Android | 系统返回键 |
| iOS | 从屏幕左边缘（24 像素以内）向右滑 |
| H5 移动端 | 不接管，保持浏览器自身行为 |

要点：

- Android 应用注册返回监听后，系统不再回退 WebView 历史，返回完全由应用自己决定
- iOS 自带的滑动返回在这个壳里没有开启，所以左边缘滑动由应用自己实现
- 终端页左边缘本来就有一套抽屉手势，那里让给抽屉，返回手势不生效
- iOS 系统不允许应用主动退出，所以在工作区首页滑返回没有动作
- 不允许再用 `history.pushState` / `history.back()` 伪造返回

### 5.4 中宽度

- 列表和详情可同屏
- 当前详情变更不应丢失左侧列表上下文
- 这些宽度下不接管系统返回和边缘滑动

### 5.5 大宽度

- 允许恢复双栏或三栏
- 但底层导航意图仍然是 `工作区 / 会话 / 工具 / 设置`
- 这些宽度下不接管系统返回和边缘滑动

## 6. 明确不允许

- 不允许“一级导航”继续藏在左抽屉里
- 不允许“工具入口”继续等价于右侧栏 tab
- 不允许“终端”在手机上继续和“会话”抢一级目的地
- 不允许手机上继续出现“前进”常驻按钮
