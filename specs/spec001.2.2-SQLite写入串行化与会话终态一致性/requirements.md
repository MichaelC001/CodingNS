# 需求文档 - SQLite 写入串行化与会话终态一致性

状态：Draft

## 简介

当前 Host 使用一个 `host.sqlite` 文件保存会话索引、状态快照和终端日志索引。Host 进程内的会话事件、工作区扫描和 WebSocket 订阅会交错执行；终端日志又由独立 writer 进程打开同一个文件。结果是写入互相等待，出现数秒级慢 SQL、`database is locked` 重试，以及运行已经结束后仍收到中断请求的错误。

本 Spec 要把写入边界收窄：同一 Host 进程的高频写入按顺序执行，长事务拆成短批次，终端日志提交可安全重试，已经结束的运行中断请求变成幂等成功。用户最终看到的是响应稳定、状态不倒退、终端日志不重复也不丢段。

## 术语表

- **Host 写入队列**：进程内统一排队并执行 SQLite 写操作的异步队列。
- **终端日志提交**：把已追加到日志文件的分段元数据写入 `terminal_log_files` 和 `terminal_log_segments`。
- **终态**：`completed`、`interrupted` 或 `failed` 等不再运行的会话状态。
- **幂等**：同一个请求因锁重试而执行多次，数据库最终只保留一份有效结果。

## 范围说明

### In Scope

- 为高频会话运行时和工作区发现写入提供共享的 Host 写入队列。
- 缩短会话索引、状态快照和终端日志索引的事务，并补充锁重试观测。
- 让终端日志提交在 SQLite 锁重试后不会重复创建分段或错误推进文件偏移。
- 将运行已经结束或不存在活动运行的 interrupt 请求处理为幂等成功，并保持数据库终态。
- 增加覆盖锁竞争、重复提交和终态中断的定向测试。

### Out of Scope

- 不迁移数据库类型，不引入 `node:sqlite`、PostgreSQL 或新的消息队列。
- 不把终端日志正文写回 SQLite，不改变现有文件日志格式。
- 不修改 provider 的中断协议或前端展示文案。
- 不通过增大 `busy_timeout` 掩盖长事务。

## 需求

### 需求 1：Host 内高频写入串行执行

**用户故事：** 作为 Host 维护者，我希望会话运行时、订阅快照和扫描回写不会在进程内互相争抢写入时机，以便 SQLite 写锁只被短事务占用。

#### 验收标准

1. WHEN 多个会话事件和扫描回写同时提交 THEN System SHALL 通过同一个 Host 写入队列按 FIFO 顺序执行写操作。
2. WHEN 写操作遇到 `SQLITE_BUSY` 或 `database is locked` THEN System SHALL 在队列内按有限次数退避重试，并记录等待和重试次数。
3. WHEN 一个写操作失败 THEN System SHALL 释放队列占用，后续写操作仍可继续执行，不能造成永久堵塞。

### 需求 2：长事务和终端日志提交可恢复

**用户故事：** 作为用户，我希望工作区扫描和终端输出持续进行时仍能打开会话，以便偶发锁竞争不会变成秒级卡顿或日志损坏。

#### 验收标准

1. WHEN 工作区发现需要写入多条索引 THEN System SHALL 使用有上限的短批次事务，并在批次之间让出事件循环。
2. WHEN 终端日志文件已经追加但索引提交因锁失败 THEN System SHALL 重试同一个幂等提交，不重复追加正文、不重复创建分段、不倒退文件偏移。
3. WHEN 终端日志提交最终失败 THEN System SHALL 返回明确错误并保留可重试状态，不能报告成功后留下不完整索引。

### 需求 3：会话终态不再产生误报

**用户故事：** 作为用户，我希望点击中断时即使运行刚刚结束也能得到稳定结果，以便不会看到无意义的 502 错误。

#### 验收标准

1. WHEN interrupt 请求到达时活动运行已经结束或不存在 THEN System SHALL 返回成功的幂等结果，并同步会话终态。
2. WHEN provider 返回 `ACTIVE_RUN_NOT_FOUND` 或等价的“运行不存在”错误 THEN System SHALL 按已结束处理，不映射成通用 502。
3. WHEN interrupt 请求与终态事件并发到达 THEN System SHALL 保证数据库中的最终状态不会从终态倒退到 `running`。

## 非功能需求

### 非功能需求 1：性能

1. 单个 Host 写操作不应因进程内排队产生无界等待；批量回写的单批事务目标为 200 ms 内。
2. 终端日志 writer 不应长时间持有 SQLite 写锁；文件追加不得放在 SQLite 事务内部。

### 非功能需求 2：可靠性

1. 锁竞争重试必须有上限，超过上限后向调用方返回失败，不允许无限循环。
2. 重试和进程重启后，日志文件与索引能通过同一请求标识恢复到一致结果。

### 非功能需求 3：可维护性

1. 新增高频后台写入必须复用 Host 写入队列，不得再创建私有 `inflight`、timer 或重试循环。
2. 日志必须包含操作 scope、排队耗时、执行耗时和重试次数，但不得记录 SQL 参数或会话正文。

## 成功定义

- 定向并发测试不再出现未处理的 `database is locked`。
- 终端日志锁竞争测试验证文件正文、文件索引和分段索引一致，重复提交不会增加分段。
- 运行终态后发送 interrupt 返回 2xx 并保留终态，不再出现 `PROVIDER_IO_ERROR`。
- `pnpm check:sqlite-runtime`、Host 类型检查和相关测试通过。
