# DTLS 指纹登记与校验

日期：2026-09-16
对应任务：`tasks.md` W4.1、W2.2
依据：`design.md` 第 5.2 节

## 这份文档回答什么

WebRTC 的端到端加密由 DTLS 承担，所以「对面到底是不是我的 Host」这个问题，
答案落在 **DTLS 证书指纹**上。这份文档把这条链路一次讲清：谁生成、谁登记、谁下发、谁校验。

不写这份的话，要搞懂它得同时读主仓库、控制面子仓库和客户端三处代码。

## 一句话

**Host 生成证书并自报指纹 → 控制面存下来 → 客户端连之前从控制面取回 → 建连时拿 SDP 里的指纹跟它对，
不一致就断开。**

关键在最后一步：**指纹是从控制面独立取回的，不是从信令通道拿的**。
所以即使信令服务器被完全控制，它也换不掉指纹——它没法同时改掉控制面里的登记值。

## 全链路

```text
Host（首次启用）              控制面                    客户端
   |                            |                         |
   | 生成自签 DTLS 证书          |                         |
   | 指纹写进绑定的              |                         |
   | host_fingerprint 字段 ---> | 存下来                   |
   |                            |                         |
   | 每次换票/心跳带指纹做一致性校验 |                         |
   | -------------------------> | 不一致 -> 409            |
   |                            |                         |
   |                            | <---- 登录 + 换票 ------- |
   |                            | ---- 票据 + 指纹 -------> |
   |                            |                         |
   | <=========== WebRTC 信令交换 SDP ===========>          |
   |                            |                         |
   |                            |        比对：控制面给的指纹
   |                            |        VS answer SDP 里的 a=fingerprint
   |                            |        不一致 -> 直接断开，无降级开关
```

## 三端各自的职责

| 端 | 做什么 | 代码位置 |
| --- | --- | --- |
| Host | 生成并持久化 DTLS 证书；把指纹登记到控制面；换票/心跳时自报指纹做一致性校验；存量绑定撞 409 时自动重新登记一次再重试 | `apps/host/src/modules/relay-tunnel/webrtc/webrtc-dtls-certificate.ts`、`relay-tunnel-webrtc-runtime-adapter.ts` |
| 控制面 | 存指纹；**换票时只下发存下来的值，不信自报值**；自报不一致返回 409；提供重新登记入口 | `apps/control-api/src/app.ts`（换票与 `dtls-fingerprint` 接口）、`dtls-fingerprint.ts`（归一化） |
| 客户端 | 从控制面取指纹；建连后从 answer SDP 解析 `a=fingerprint` 并比对；不一致抛错断开 | `apps/user-app/src/network/webrtc/dtls-fingerprint.ts` |

**Host 的证书存在哪**：复用 `instance_relay_tunnel_identity` 那一行，DTLS 材料是同一行的新列
（不新开表）。老的 x25519 材料还留着，等 W6.1 清理。

## 指纹格式：三种写法必须能对上

这是最容易出错的一环。同一个指纹在不同环节的写法天然不统一：

| 环节 | 典型写法 |
| --- | --- |
| Host 生成 | `sha-256 A1:B2:C3:...`（算法名小写、十六进制大写、冒号分隔） |
| 控制面存储 | 原样存 Host 报上来的写法 |
| SDP 里 | `a=fingerprint:sha-256 A1:B2:C3:...` |
| 有的实现 | `SHA256:A1B2C3...`、`sha-256 a1-b2-c3-...` |

**所以两端都必须先归一化再比，不能逐字符比。** 规则：

- 能认出标准 SHA-256 摘要（32 字节 = 64 个十六进制字符）时，**只比摘要本身**，
  忽略算法前缀、大小写、分隔符
- 认不出来时退回「去空格 + 转大写」的整串比较，**不做猜测性裁剪**

**只处理写法差异，不降低强度**：归一化不会把两个不同的摘要判成相等。

程序里有两份实现，必须保持一致：

- 控制面：`apps/control-api/src/dtls-fingerprint.ts`
- 客户端：`apps/user-app/src/network/webrtc/dtls-fingerprint.ts`

## 存量绑定怎么迁移

换成 WebRTC 之前，绑定的 `host_fingerprint` 里存的是**自建 x25519 公钥指纹**。
升级后的 Host 第一次换票时会撞上：

```text
409 HOST_DTLS_FINGERPRINT_MISMATCH
```

detail 里会同时给出「绑定记录里是 X，本次上报的是 Y」。

**这是预期路径，不是故障。** Host 会自动做一次：

1. 调 `POST /api/v1/hosts/:bindingId/dtls-fingerprint` 把本机的 DTLS 指纹登记上去
2. 重试原来的换票 / 心跳请求
3. **只自动重试一次**。重新登记本身也失败（401 登录失效 / 404 绑定不存在 / 409 指纹被别的 Host 占用）
   才上报成需要用户处理的错误，并写清该做什么

用户侧**不需要任何操作**：不用重新绑定、不用换域名、界面上也不会多出步骤。

## 证书轮换怎么办

**目前没有界面，只能手工。** 需要换证书时：

```bash
# 用绑定归属账号登录后拿到 accessToken
curl -X POST "https://<控制站>/api/v1/hosts/<bindingId>/dtls-fingerprint" \
  -H "authorization: Bearer <accessToken>" \
  -H "content-type: application/json" \
  -d '{"hostDtlsFingerprint":"sha-256 <新指纹>"}'
```

注意这个接口**先校验绑定归属再写入**——顺序反了会变成猜到 bindingId 就能改别人的指纹。

**手工换证书期间，已经连着的老客户端不会立刻断**，但下次重连会校验新指纹。
如果客户端拿到的还是旧指纹，会被它自己拒绝——所以换证书要当作一次运维动作来做，别随手换。

## 怎么验证

**控制面侧（接口级）**：

```bash
cd apps/codingns-proxy
pnpm --filter @codingns-proxy/control-api test
```

覆盖：自报指纹不一致被拒、同一指纹不同写法按一致处理、重新登记后客户端拿到新指纹、
重新登记要求登录与归属正确。

**Host 侧**：

```bash
pnpm --dir apps/host test -- tests/integration/relay-tunnel-webrtc-runtime-adapter.test.ts
```

覆盖：换票带上 DTLS 指纹、撞 409 自动重新登记后成功、只重试一次、
以及「绑定失效时抛的是服务层认识的错误类型与错误码」（这条是防用户永远卡在 error 的回归测试）。

**客户端侧**：

```bash
pnpm --dir apps/user-app test -- src/network/webrtc/dtls-fingerprint.test.ts
```

**端到端**：构造指纹不匹配的场景（比如把绑定里的指纹改成别的），确认客户端连接被拒、
且给出的是「对方的身份指纹和你的 Host 记录不一致」这种可读原因，而不是裸错误码。

## 明确不做

- 不做「指纹不符但允许继续」的降级开关，任何情况下都不提供绕过
- 不做证书轮换界面（要做的话单开一个任务）
- 不做证书有效期管理与自动续期
- 不用 Host 的长期身份密钥对（x25519 那套随 W6.1 删除）
