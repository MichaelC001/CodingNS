# 需求文档 - spec002.1.2 会话索引与显式扫描

状态：Draft

## 需求 1：创建会话立即写入 Host 索引

1. 创建成功的会话必须在同一业务流程中写入 `session_bindings` 和 `session_index`。
2. provider 原生会话创建成功但 Host 写入失败时，必须记录可恢复错误，不能返回“创建成功”。
3. 不得为了确认新会话而再次扫描整个工作区。

## 需求 2：普通列表只读 SQLite

1. 工作区打开、侧边栏刷新、会话列表刷新只能读取 Host SQLite 索引。
2. 这些读路径不得调用 provider discovery、读取 provider 历史目录或启动扫描 helper。
3. 未启用 provider 不得参与任何扫描或历史读取。

## 需求 3：显式全量扫描

1. 新建会话界面提供“扫描当前工作目录会话”按钮。
2. 点击后按当前工作区和已启用 provider 执行一次全量扫描。
3. 扫描任务必须走 `TaskManager` 的 `helper_process`，按工作区 key 去重，并返回扫描进度/结果。
4. 扫描结果只能新增或更新 SQLite 索引，不得删除用户已有会话；删除必须走独立清理流程。

## 需求 4：虚拟会话延迟加载

1. 普通列表不加载虚拟会话、子 Agent 或完整历史。
2. 用户打开具体会话后，才按 provider 和 rawStoreRef 加载首屏历史。
3. 虚拟会话列表只能由会话详情请求触发，并使用增量/分页读取。

## 需求 5：刷新边界

1. watcher、广播和工作台刷新只更新脏标记，不得直接执行全量扫描。
2. 新建会话成功后的刷新只更新单条索引和当前会话状态。
3. 显式扫描按钮重复点击必须复用同一个任务，不得并发扫描同一工作区。

## 非功能需求

- 普通会话列表请求的 provider discovery 调用次数为 0。
- 普通刷新不得产生 provider 历史文件读取指标。
- 全量扫描必须可观测：工作区、provider、扫描文件数、跳过数、解析数、字节数、耗时和触发源均可查询。
