## 2. RPC 基线

Pi RPC 启动方式：

```bash
pi --mode rpc
```

协议特点：

- stdin/stdout 使用严格 JSONL。
- 每行一个 JSON 对象，记录分隔符必须是 LF。
- response 使用 `type: "response"`，可用 `id` 做关联。
- 事件异步写到 stdout。
- `prompt` 的成功 response 只代表请求已接受、排队或立即处理。
- `agent_settled` 才代表 session 级运行真正结束。
- 但 `agent_settled` 会被扩展的 `agent_settled` handler 阻塞：上游是先 `await` 扩展 handler，再把这个事件发给 RPC 客户端。计划模式扩展在这个 handler 里等用户点审批，所以 `agent_end` 到了之后 `agent_settled` 可能长时间不来（实测等待 15 秒以上仍无）。判断"这一轮跑完没有"不能只等 `agent_settled`。
- `message_update` 是增量，`message_end.message` 是完整消息快照。
- 工具事件包括 `tool_execution_start/update/end`。
- 扩展交互使用 `extension_ui_request/extension_ui_response`。

## 4. 能力结论

### 可以直接接入

- 新建/继续会话
- 文本、思考、工具调用和工具结果事件
- steer、follow-up、clear queue、中断
- 模型列表和模型切换
- 图片输入
- 会话历史和树结构
- Fork、Clone、重命名
- 基本 usage
- 扩展 select/confirm/input/editor
- Plan Mode 的基础 select 审批（需要扩展）

### 需要 CodingNS 适配层

- session JSONL 扫描、分页和增量解析
- 普通文件附件路径/提示词协议
- 删除和归档语义
- 扩展 UI 到 CodingNS interaction/permission 的映射
- RPC 兼容 question 工具
- Plan Mode 扩展的安全加载和审批回传
- capability 和前端门控

### 不能直接等价接入

- DSH Remote 的事件重放
- Host 重启后接管仍在执行的 turn
- 原生 Agent Preset/subagent
- `session/control`
- DSH 级别的结构化权限范围审批

## 5. 测试限制

本次基线没有可用的真实模型 API Key，因此没有验证真实供应商的完整文本流、工具调用执行和 Plan 扩展实际 turn。协议、进程生命周期、错误路径和官方客户端已经验证；真实模型联调应作为后续实现阶段的可选冒烟，不得替代 fixture 回归。
