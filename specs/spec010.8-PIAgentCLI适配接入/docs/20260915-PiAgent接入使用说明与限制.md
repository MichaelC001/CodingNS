# Pi Agent 接入使用说明与限制

日期：2026-09-15

这份文档写给接手人和使用者：怎么让 Pi 在 CodingNS 里跑起来、数据放在哪、哪些能力不要指望。

## 1. 前置条件

- Pi CLI：`npm install --global --ignore-scripts @earendil-works/pi-coding-agent@0.85.1`
- Node：`>=22.19.0`（实测 22.22.0）
- 至少配置一个可用的模型供应商。Pi 的登录信息在 `~/.pi/agent/auth.json`，自定义供应商和模型列表在 `~/.pi/agent/models-store.json`。

验证安装：

```bash
pi --version                 # 期望 0.85.1
pi --mode rpc <<< '{"type":"get_available_models","id":"c1"}'
```

## 2. Host 配置项

| 配置 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `piCliPath` | `CODINGNS_PI_COMMAND` / `PI_COMMAND` | `pi` | Pi 可执行文件路径 |
| `piDataRootDir` | 无（跟随数据库目录） | `mkdir(databasePath)` | Pi 数据根目录，见下一节 |
| `piExtensionPaths` | `CODINGNS_PI_EXTENSIONS` | 仓库内两个受控扩展 | 扩展白名单，逗号分隔；显式配置会整体覆盖默认值 |
| `piQuestionExtensionAvailable` | 无 | 由白名单推导 | question 扩展是否可用 |
| `piPlanExtensionAvailable` | 无 | 由白名单推导 | Plan Mode 扩展是否可用 |

## 3. 数据放在哪

Pi 的 agent 目录和 session 目录按**工作区**隔离：

```
<piDataRootDir>/pi-workspaces/<工作区 slug>/pi-agent/           # PI_CODING_AGENT_DIR
<piDataRootDir>/pi-workspaces/<工作区 slug>/pi-agent/sessions/  # PI_CODING_AGENT_SESSION_DIR
```

没有配置数据根目录时退回 `<workspacePath>/.codingns/pi/`。

为什么不是每个 CodingNS 会话一个目录：Pi 的会话发现只能扫一个 session 根目录，按会话切分会话目录会导致已有 Pi 会话永远列不出来。按工作区隔离同样满足"不串用用户全局配置和其他工作区配置"。

**凭据同步**：Host 启动 Pi 前会把用户全局 `~/.pi/agent/auth.json` 和 `models-store.json` 复制进工作区 agent 目录（只在缺失或源更新时复制，不反向写回）。这样既能用上用户已经配好的模型，又不会让 Pi 往全局目录写会话。

**HOME 不覆盖**：默认不动 `HOME`。Pi 的配置目录已经由 `PI_CODING_AGENT_DIR` 隔离，覆盖 `HOME` 反而会破坏工作区里的 git/npm/ssh。

## 4. 受控扩展

Pi 扩展拥有进程级权限，所以：

- 启动参数固定带 `--no-extensions`，工作区里的 `.pi/extensions` 永远不会被自动加载。
- 只加载 `piExtensionPaths` 里列出的文件。
- 默认白名单是仓库内的两个扩展：
  - `apps/host/pi-extensions/question-rpc/index.ts`：RPC 兼容的 `question` 工具，只用 `select` + `input`。
  - `apps/host/pi-extensions/plan-mode-rpc/index.ts`：只读计划模式，拦截 edit/write 和破坏性 bash，计划生成后弹审批。
- 扩展不可用时，能力快照里的 limitations 会写明，对应的前端入口关闭。

启用 Plan 模式：Node 侧设置 `PI_PLAN_MODE=1`，或在 Pi 命令行加 `--plan`。

## 5. 计划模式与审批

- 会话页 composer 上有「计划模式」开关，只在 provider 声明 `supportsPlanMode` 时显示（Pi 在受控 plan-mode 扩展可用时为 true）。
- 打开后发送消息会带 `permissionMode=plan`，Host 映射成 `PI_PLAN_MODE=1` 注入 Pi 子进程；关掉即恢复完整权限。
- 计划模式下 edit/write 和破坏性命令（含 PowerShell 写动词）会被扩展拦下，只允许读取、搜索和查询类命令。
- 计划生成后，扩展用 `select` 征求下一步；Host 把它渲染成 `plan_approval` 卡片（批准计划/继续完善/修改/取消），选择结果按原 request id 回传。
- 扩展的交互请求可能比 `agent_settled` 晚到，Host 的收尾宽限期（`settleGraceMs`，默认 1.5s）会等挂起的交互处理完再关进程。
- 审批卡片弹出时，这一轮的运行状态已经收敛成“已完成”（Pi 的 `agent_end` 一到就收敛），所以界面不会一直转圈；审批期间 Pi 进程仍在运行，选完之后会话按新的一轮继续。

## 6. 用量、费用与上下文水位

| 指标 | 来源 | 说明 |
| --- | --- | --- |
| input/output/cache/reasoning tokens | 会话文件里每条 assistant 消息的 usage | 按模型归因，缺失字段保持缺失 |
| 费用 | Pi 自己算出的 usage.cost | 记为 `provider-native` + `coverage: complete`，Host 直接落账单，不等价于价格表估算 |
| 上下文水位 | 最后一条 assistant 消息的 input+cacheRead+cacheWrite | 上下文窗口从用户 Pi 的 `models-store.json` 按 provider/model 查；查不到窗口时整个水位返回 null |

## 7. 附件协议

| 附件 | 行为 |
| --- | --- |
| 图片（png/jpeg/webp/gif，≤10MB） | 转成 Pi 的 base64 image content |
| 工作区内文本文件（≤256KB） | 内联成带文件名和相对路径的文本块 |
| 更大的文件或二进制文件 | 只发工作区相对路径，并提示模型用 read 工具读取 |
| 工作区外的路径 | 直接失败（`PI_ATTACHMENT_PATH_FORBIDDEN`），不会静默降级 |
| 当前模型不支持图片输入 | 直接失败（`PI_ATTACHMENT_MODEL_UNSUPPORTED_IMAGE`），提示换模型或去掉图片 |

图片这一条是踩过坑的：Pi 在模型不声明图片输入时会把图片丢掉，模型只会回一句"我看不到图"，
用户以为发出去了其实没有。现在适配器会先查用户 Pi 模型库里的 `input` 声明，
模型明确不支持时直接拦住。模型库里查不到这个模型时不做判断（未知不等于不支持）。

路径校验同时比较解析路径和 realpath（含最长存在祖先的规范化），`..` 和符号链接都绕不出去。

## 8. 删除与归档

- 删除：Host 拒绝删除运行中的会话；适配器再校验文件必须落在受控 session 根目录内，然后只删单个文件并清理解析缓存。
- 归档：写 `<sessionDir>/.codingns-pi-meta.json`，Pi 物理文件保留，取消归档可恢复。Pi 没有原生归档能力，也没有伪造 `supportsSessionArchive`。

## 9. 错误码

| 错误码 | 含义 |
| --- | --- |
| `PI_CLI_NOT_FOUND` | 找不到 pi 可执行文件 |
| `PI_RPC_PROTOCOL_ERROR` | stdout 出现非法 JSON、非对象行或没有 id 的 response |
| `PI_RPC_LINE_TOO_LARGE` | 单行超过上限被丢弃 |
| `PI_RPC_RESPONSE_TIMEOUT` | 命令等待 response 超时 |
| `PI_RPC_COMMAND_FAILED` | Pi 返回 `success:false` |
| `PI_PROMPT_REJECTED` | prompt 被拒绝（例如没有对应供应商的密钥） |
| `PI_AGENT_FAILED` | 进程在 `agent_settled` 之前退出 |
| `PI_SESSION_NOT_FOUND` | 会话文件不存在或缺少继续会话所需的绑定 |
| `PI_SESSION_FILE_OUTSIDE_ROOT` | 会话文件不在受控 session 根目录内 |
| `PI_FORK_SOURCE_NOT_FOUND` / `PI_FORK_CANCELLED` | 分叉起点找不到 / 扩展取消了分叉 |
| `PI_ATTACHMENT_PATH_FORBIDDEN` / `PI_ATTACHMENT_TOO_LARGE` | 附件越界 / 超限 |
| `PI_ATTACHMENT_MODEL_UNSUPPORTED_IMAGE` | 当前模型不接受图片输入 |
| `PI_SEND_REQUIRES_ACTIVE_RUNTIME` | 试图绕过运行中的 RPC 进程直接发消息 |

## 10. 明确做不到的事

- 没有 DSH Remote 的会话事件重放。
- 不能在 Host 重启后接管仍在执行的 turn。
- 没有原生 Agent Preset、subagent 和 `session/control`。
- 扩展交互只能表达 select/confirm/input/editor，不能给出 DSH 级别的结构化权限范围审批。
- token usage 来自 Pi 事件累计，口径与 DSH projection 不完全一致。
- 普通文件没有原生 file content block，只能走文本注入或路径协议。

## 11. 回归命令

```bash
# 核心协议与会话解析（不依赖模型密钥）
pnpm --dir packages/session-sync-core build
node --test --test-timeout=40000 packages/session-sync-core/tests/pi-*.test.mjs

# Host 与前端
pnpm --dir apps/host exec tsc --noEmit -p tsconfig.json
pnpm --dir apps/user-app exec tsc --noEmit -p tsconfig.json
pnpm --dir apps/host test -- --run \
  tests/integration/pi-extension-ui-bridge.test.ts \
  tests/integration/pi-plan-mode-policy.test.ts \
  tests/integration/session-stats-snapshot-repository.test.ts
pnpm --dir apps/user-app test -- --run src/features/conversation/capability/provider-ui.test.ts

# 真实模型冒烟（需要已配置供应商）
node scripts/pi-live-smoke.mjs   # 见下节说明
```

真实模型冒烟（`scripts/pi-live-smoke.mjs`）覆盖 8 个场景：单轮文本 + usage、工具调用、steer、Fork 后继续、question 交互、Plan 审批与只读拦截、图片附件、clear_queue。没有密钥时这些都不作为协议测试的前置条件。
